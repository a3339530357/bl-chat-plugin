# 长期记忆 V3 实现与操作

阶段 0、1 的原料契约见 `memory-v3-stage1.md`。本文件记录后续实现。

## 阶段 2：记忆存储与管理

`MemoryStoreV3` 按 bot/group 管理 facts、events、evidence、review、revisions、tombstones、batches HASH，以及事件时间 ZSET。单次快照在一个 Redis 脚本中读取，所有变更通过 memoryRevision/epoch CAS 提交。

- 批次 ID 由范围、原编码来源、作用域和提取版本确定；同一提交重试只返回已有凭据。
- 校验来源范围、版本和 workerToken 后再写。执行时设置 writePending，成功后清除；残留标记使读写和回收拒绝执行，不能静默跳过或自动抹掉。
- 每条接受或待确认记忆保留引用、完整支持消息及邻近语境；上下文尾部另存供下一批使用。
- 事实按人物/槽位匹配；多值偏好使用 `preference:<目标>` 槽位。变化和纠错都保留旧修订；较旧的消息不能自动覆盖新事实。
- 被删除的槽位、被驳回的候选留 tombstone；重试不能自动复活。主人确认和撤销属于显式人工恢复。
- `sourceReclaimedThrough` 单独跟踪实际回收范围，不再假定 extractedThrough 等于原料删除位置。回收每次最多 64 条，默认保留末尾 20 条语境；未提交来源不回收。

主人在目标群可使用以下命令，ID 使用列表中的完整 ID：

```text
#记忆待确认
#记忆证据 <事实/事件/待确认ID>
#记忆确认 <待确认ID>
#记忆驳回 <待确认ID>
#记忆修正 <事实/事件ID> {"text":"修正后的描述","value":"事实的新值"}
#记忆撤销修订 <事实/事件ID>
#记忆删除条目 <事实/事件ID>
```

修正目前允许修改 text/value/core；身份、槽位、时间或事件参与者需要通过带证据的重新整理/确认处理，不能用自由 JSON 改写对象身份。待确认项的目标已经变化时拒绝确认，要求重新整理或明确修正当前对象。

上述操作仅作用于当前群；主人身份在命令层和存储管理 API 中均检查。证据不足、引用归属不明、玩笑、过旧证据或槽位冲突不会进入自动生效视图。

数据体量按两个小群设计，快照读取当前集合；单次提交上限为 64 条来源、100 个候选、500 处对象变更、2 MiB 编码计划。超限报错，不推进游标。
