# 长期记忆 V3 实现与操作

阶段 0、1 的原料契约见 `memory-v3-stage1.md`。本文件记录后续实现。

## 阶段 2：记忆存储与管理

`MemoryStoreV3` 按 bot/group 管理 facts、events、evidence、review、revisions、tombstones、batches HASH，以及事件时间 ZSET。单次快照在一个 Redis 脚本中读取，所有变更通过 memoryRevision/epoch CAS 提交。

- 批次 ID 由范围、原编码来源、作用域和提取版本确定；同一提交重试只返回已有凭据。
- 校验来源范围、版本和 workerToken 后再写。执行时设置 writePending，成功后清除；残留标记使读写和回收拒绝执行，不能静默跳过或自动抹掉。
- 每条接受或待确认记忆保留引用、完整支持消息及邻近语境；上下文尾部另存供下一批使用。
- 事实按人物/槽位匹配；多值偏好使用 `preference:<目标>` 槽位。变化和纠错都保留旧修订；较旧的消息不能自动覆盖新事实。
- 被删除的槽位、被驳回的候选留 tombstone；重试不能自动复活。主人确认和撤销属于显式人工恢复。
- `sourceReclaimedThrough` 单独跟踪实际回收范围，不再假定 extractedThrough 等于原料删除位置。回收每次最多 64 条，默认保留末尾 20 条语境；未提交来源不回收。

主人在目标群可使用以下命令，ID 使用列表中的完整 ID：

```text
#记忆待确认
#记忆证据 <事实/事件/待确认ID>
#记忆确认 <待确认ID>
#记忆驳回 <待确认ID>
#记忆修正 <事实/事件ID> {"text":"修正后的描述","value":"事实的新值"}
#记忆撤销修订 <事实/事件ID>
#记忆删除条目 <事实/事件ID>
```

修正目前允许修改 text/value/core；身份、槽位、时间或事件参与者需要通过带证据的重新整理/确认处理，不能用自由 JSON 改写对象身份。待确认项的目标已经变化时拒绝确认，要求重新整理或明确修正当前对象。

上述操作仅作用于当前群；主人身份在命令层和存储管理 API 中均检查。证据不足、引用归属不明、玩笑、过旧证据或槽位冲突不会进入自动生效视图。

数据体量按两个小群设计，快照读取当前集合；单次提交上限为 64 条来源、100 个候选、500 处对象变更、2 MiB 编码计划。超限报错，不推进游标。

## 阶段 3：主人触发的后台整理

`#整理记忆` 创建或恢复当前群任务，立即返回任务 ID 和固定截止序号；`#整理记忆进度` 查看状态。每群一个任务，全局模型调用串行，不进入主对话 session 或并发计数。完成后不自动追赶新消息。

模型沿用 `memoryAiConfig.memoryAiUrl/memoryAiApikey/memoryAiModel`，保留旧配置字段。测试注入假模型，禁止真实网络请求。`memoryV3.organizeEnabled` 只控制整理，关闭时中止记忆请求、暂停任务并保留原料；重新启用可恢复原截止范围。

任务元数据在 `job:active` 与 `jobs` 中保存，`ytbot:memory:v3:jobScopes` 记录有过任务的作用域。恢复只运行既有 queued/running/paused 任务，不创建新的整理范围。进程重启后要等旧 lease 过期再接管，恢复计时器最多每分钟检查一次。failed 任务由主人再次发命令恢复，不无限自动重试。

批次边界、输入摘要、模型版本、长消息分片和已完成分片结果持久化。上下文与已有事实按预算选择；长消息原件仍完整保留，只对模型输入做分片。分片和候选 JSON 以字符串经过 Lua，避免空数组变形。使用固定来源边界重试；模型截断时只把当前模型输入分成子片，先持久记录父子摘要，再处理子片，最终仍以原来源范围提交一次。无法继续拆分、超过重试或提交大小上限则保留失败状态和原料。

提取和证据审核是两个独立调用，均有独立超时/取消。合法空结果可以提交；无效 JSON、截断或不完整审核结果不能当空结果推进。相对日期以原消息时间换算；历法、年份无依据时进入歧义确认。独立审核仍是模型判断，不能保证零误记；程序检查引用和身份，并保留来源与审核依据供主人复核。

## 阶段 4：双轨召回与临时 tail

`MemoryRetrieverV3.buildMemoryTail()` 一次读取同群的一致快照。active/core 事实按 QQ 和槽位排序，全量常驻；核心视图按 scope+memoryRevision 缓存。超过 coreTokens 时显式报错并通过状态命令展示，主对话可以降级继续，不偷偷截断后冒称全量。

事件以当前文本、已解析的引用/当前用户内容、明确 @ 和最多十条最近真实群消息构建 query。本地中文关键词/二元组结合人物、年份排序；支持“今年/去年/前年”，不对旧事件做强时间衰减。低相关结果返回空，最多八条并限制独立 token 预算。重名昵称不自动映射到单个 QQ，明确 @ 可以消歧。时间精度和 planned/occurred/cancelled/unknown 均在输出中保留。

新记忆通过独立 `memoryTail` 参数经过 `apps/chat.js → preparePromptCacheTurn → buildTurnReferenceContent`。它不进入 header、referenceFacts 或 planContextNotes；CacheTurn 精确剥离本轮后缀后再提交历史。V1 回退也只给当前用户行加后缀，并在保存历史前去掉。

V3 开始使用后，账本记录 memoryReferencesRetired 标记：旧个人/群记忆注记退役，基线不再恢复它们；旧 writer 的提交也会将这些键维持为 tombstone。已有块不因新记忆更新而改写，仍由原有裁剪/注记压缩机制处理。

`memoryV3.injectEnabled=false` 关闭新注入而不删除记忆或来源；读取失败、空记忆和预算超限有不同诊断状态。当前不加入在线 embedding/LLM 检索调用，检索策略可替换 `retrieveEvents()` 接口。

## 阶段 5：导入、旧入口退役与回收

主人在目标群发送 `#导入历史记忆`，后台导入阶段 1 已保全的 raw、近期消息和回放；不触发模型。结构化消息按原身份去重，回放只选一份用户行投影，机器人、工具和上下文注记不导入。无法恢复 QQ/日期的回放标为 legacy_content，不能自动成为确定事实或已发生事件。原快照的缺口保留在导入结果中。

旧 `ytbot:memory:` 与 `ytbot:memory:v2:` 数据只读扫描当前群。旧事实变成待主人确认的候选，同一群同一人的相同内容跨旧格式合并去重；旧数据不修改、不删除。需要处理导入后的新原料时，再发 `#整理记忆`。导入与实时入账可重叠；若同时有记忆管理变更造成 CAS 冲突，导入保留已完成结果并报告失败，可重试。

运行时已不再实例化旧 MemoryManager，也不再写旧关系分。旧模块源码保留给回归测试与格式参考，生产入口由 MemoryService/MemoryAdminV3 承担。旧 memorySystem 字段保留供配置兼容，V3 不读取其提取、衰减或召回参数；锅巴页面明确标为旧字段。

旧命令名称继续可用：`#我的记忆`、`#群记忆`、`#搜索记忆`、`#删除记忆`、`#清空我的记忆`、`#清空群记忆`、`#禁用我的记忆`、`#启用我的记忆`。本人可以遗忘或禁用自己的个人事实；群级清空、证据审核和修正要求主人。遗忘会记录墓碑及旧原料抑制水位，不删除已保全原料；禁用会停止该成员的后续提取输入及个人事实注入，但仍保留原料。此处没有实现一键擦除所有证据、审计、归档的隐私删除工具。

成功整理后默认 `reclaimEnabled=true`，按已提交水位分批回收，仍保留末尾 20 条原料语境。证据、歧义项和任务审计另存；`sourcePendingBytes` 表示待整理字节，`pendingBytes` 表示包括保留语境在内的驻留原料字节。提醒按未整理范围判断，回收不影响未处理来源。可将 reclaimEnabled 设为 false 暂缓回收。

每个分片保存实际模型输入、模型名、候选与审核依据，不保存 API key；阶段 3 的输入 hash 可用于对照来源。审计与证据目前不自动过期，因此原料回收不会使全部存储占用归零。在线召回只读取 meta/facts/events，不把累积审计、修订或原始上下文整批拉入主对话路径。

任务记录提供批次数、重试数、最近错误、最近模型请求耗时和总耗时；`#整理记忆进度` 也能查看最近完成的任务。测试证明等待模型时事件循环和新消息入账可继续，但不把本地假模型耗时当成生产性能结论。

## 部署前操作顺序（本次不执行部署）

1. 显式设置 `memorySource.groups` 为需要保全原料的群；先把 `memoryV3.groups` 设为第一个试用群。未配置 memoryV3.groups 会沿用来源群范围，不要误以为默认只启用一个群。
2. 核实 memoryAiConfig 的实际渠道、模型、权限与输出兼容性；本次所有提取测试均为假模型，没有验证 8045 或免费渠道的可用性、速率和真实误记率。
3. 检查 Redis 持久化、备份和内存余量。未整理来源无 TTL、无容量淘汰；应用层保留不等于宿主机故障下零损失。
4. 第一群依次查看状态、导入历史、手动整理、核对证据/歧义及对话注入，再将第二群加入 memoryV3.groups。代码测试覆盖这一选择过程；本次没有在线执行。
5. 如需回退，将 injectEnabled 和 organizeEnabled 关闭，来源继续保全；不删除数据、不恢复旧自动提取、不重置游标。恢复时沿既有任务和数据版本继续。

边界：模型审核仍可能误解玩笑；中文关键词召回会漏掉纯同义表达；事件跨很远的批次可能无法自动合并，进入人工处理；媒体不额外执行 OCR/语音识别；超大批次或对象计划会失败保留原料，不静默跳过；writePending 残留需检查实际数据后人工恢复，不能直接清掉掩盖部分写入。当前面向单实例 Redis 和小群数据规模。
